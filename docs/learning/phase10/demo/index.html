SNS — Pub/Sub ファンアウト通知

Amazon SNS の Topic にメッセージを Publish すると、すべての Subscriber へ同時に配信される「ファンアウト」を体験する。フィルタポリシーで条件に合う購読者だけに届ける仕組みも確認できる。

SNS Topic / Subscription ファンアウト フィルタポリシー FIFO トピック

メッセージ属性を設定して「Publish」するとファンアウトが走る。フィルタポリシーに合わない購読者はスキップされる。

💡 定番パターン: SNS → 複数 SQS のファンアウト。各 SQS Queue を独立したサービス（注文処理・在庫更新・通知）が Pull。疎結合な扇形配信を実現。
学ぶポイント
  • Pub/Sub と Queue の違い SNS は push 型で複数購読者へ同時配信、SQS は pull 型で 1 コンシューマが取り出す。SNS は「広報」、SQS は「郵便受け」のイメージ。
  • Topic / Subscription / Protocol 1 トピックに Email / SMS / SQS / Lambda / HTTP など多様な購読を束ねる。配信先のプロトコルを変えても Publisher 側のコードは変わらない。
  • ファンアウトパターン SNS → 複数 SQS で各サービスが独立に処理。疎結合な扇形配信の定番パターン。サービス追加は SNS に Subscription を追加するだけ。
  • メッセージフィルタリング 属性に対するフィルタポリシーで購読側が必要なメッセージだけ受け取る。FIFO トピックで MessageGroupId ごとの順序保証が可能（スループット制限あり）。
